Abstract

This report documents an extension of a portable commercial off-the-shelf (COTS) millimetre-wave radar prototype based on the Texas Instruments IWR6843ISK-ODS, DCA1000EVM and NVIDIA Jetson Orin Nano. The inherited repository contained two distinct processing approaches: a conventional range–Doppler, constant-false-alarm-rate, point-cloud and convolutional-neural-network pipeline; and a periodic-micro-motion (PMM) pipeline using spectrum folding, background subtraction, continuity-constrained tracking, particle filtering and long short-term memory classification. The present extension does not replace those approaches. It preserves the deployed PMM baseline and adds three experimental PMM operating modes: a lower-slope long-range TDM-MIMO waveform, coherent receive-sector beamforming over the twelve-element virtual array, and a non-MIMO single-transmitter/four-receiver electronic receive scan. A touchscreen-oriented graphical interface, tactical top-down display, live calibration/readiness indication, target-attached status annotation and structured performance logging were also developed. The waveform and receive-beam changes address different limitations: the lower chirp slope increases sampled unambiguous range but does not itself improve the radar link budget, whereas coherent receive combination can provide array-processing gain inside a restricted look sector. Final controlled hardware testing has not yet been completed; range, detection probability, false-alarm and tracking results are therefore intentionally left blank.

1 Introduction

1.1 Context

Small UAVs are difficult radar targets because their body radar cross section is low, their return varies with aspect, and hovering produces little translational Doppler. The project’s portable architecture uses a 60–64 GHz IWR6843ISK-ODS radar, a DCA1000EVM raw-data capture card and a Jetson Orin Nano for local processing and display. Earlier team work established the hardware start-up sequence, packet acquisition, calibration, target processing and UAV/non-UAV inference. It also established two conceptually different processing pipelines: a broad conventional moving-target pipeline and a rotor-sensitive PMM pipeline.

1.2 Objective of the extension

The extension investigates whether the existing hardware can obtain a more useful range envelope or directional sensitivity without replacing the radar board. Four selectable PMM configurations are retained in one isolated application for controlled comparison. The work also aims to make the platform practical on a portable touchscreen by reducing terminal dependence and presenting clear calibration, readiness and target state information.

1.3 Research questions

  1. Are the two inherited processing approaches still preserved and operationally accessible?
  2. What physical or processing quantity is changed by each added mode?
  3. Does a lower-slope waveform, coherent receive-sector processing or single-transmitter receive scanning increase useful target range or tracking continuity under matched conditions?
  4. Can these modes run within the Jetson’s 100 ms PMM frame period without capture or processing loss?

2 Inherited processing approaches and current availability

2.1 Original conventional approach

The conventional implementation performs a range FFT and TDM-aware Doppler FFT, learns a clutter reference, applies two-dimensional ordered-statistic CFAR, estimates angle, converts detections to XYZ points, clusters them with DBSCAN and maintains a constant-velocity target track. A target-gated micro-Doppler history feeds a CNN classifier. This path is general-purpose because it does not require a periodic rotor response, but a weak or hovering target must first produce sufficient conventional detection evidence.

2.2 Original PMM approach

The PMM implementation forms range–Doppler data, folds the Doppler spectrum over candidate periodicities, subtracts a calibrated projected background, and follows a continuity-constrained maximum through range and time. Particle filtering and track lifecycle logic provide smoothed range/velocity state. Capon-based angular processing estimates azimuth and elevation, and a 36-by-64 Doppler–time sequence can feed an LSTM UAV/non-UAV classifier. This path is specialised toward periodic rotary-wing evidence and is the processing basis used by all four modes in the currently deployed extension.

3.1 Mode 1 — retained control

Mode 1 deliberately retains the original PMM waveform and feature contract. Its 46.875 MHz/µs slope and 6.25 MS/s ADC sampling give an approximate 20 m sampled unambiguous range and approximately 0.078 m range-bin spacing. It is the required reference for deciding whether later modes improve useful detection rather than merely changing display limits or thresholds. The existing LSTM model is fingerprinted to this profile and remains valid only here.

3.2 Mode 2 — lower-slope long-range waveform

Mode 2 follows the long-chirp direction reported in the mmHawkeye literature: 60.25 GHz start frequency, 9.994 MHz/µs slope, 6.25 MS/s sampling and a 900 µs chirp repetition period. The implementation retains 32 complete three-transmitter groups, giving 96 chirps per frame. Lowering slope increases the sampled unambiguous range to approximately 93.8 m, but the ADC-observed bandwidth gives coarser range bins of approximately 0.366 m. The current GUI initially limits acquisition/display to 20 m for controlled testing; changing the mathematical range gate does not demonstrate detection at that range.

3.3 Mode 3 — coherent sector receive beamforming

Mode 3 uses the Mode 2 RF waveform but coherently combines the twelve TDM virtual channels. A small beam bank covers five azimuth positions and three elevation positions around the operator’s selected centre. The strongest coherent response is retained for each range/Doppler cell. Because each transmitter fires at a different time, the implementation compensates Doppler-dependent inter-transmitter phase before spatial combination. A non-coherent channel-average floor is retained so an imperfect phase calibration cannot suppress a target solely through destructive summation.

An ideal twelve-channel coherent combination has an upper-bound power gain of about 10.8 dB relative to one channel. Real improvement over the existing non-coherent average will be lower and depends on calibration, target direction, multipath and motion. This is host-side receive beamforming; it does not steer transmitter phase and does not increase EIRP.

3.4 Mode 4 — single-transmitter receive scanning

Mode 4 disables TDM-MIMO and uses one transmitter with four receivers. It scans a two-dimensional receive steering grid from −60° to +60° in azimuth and elevation. The strongest beam provides coarse bearing/elevation information after PMM range detection. A tactical top-down PPI plots cross-range, down-range, target trail, slant range and relative altitude, with altitude estimated as Rsin(elevation). The four physical receive channels provide a smaller aperture and less ideal coherent gain than Mode 3’s twelve virtual channels. Mode 4 is therefore an operator/display and non-MIMO receive-scan experiment, not a claim of military-style transmit AESA operation.

Transmit steering boundary. Modes 3 and 4 steer only the host-side receive weights. The standard board/profile path does not apply validated multi-transmitter phase steering. Mode 4 intentionally uses one transmitter and therefore does not increase transmit gain or EIRP.

4 Technical basis for range and sensitivity changes

4.1 Sampled range

For FMCW sampling rate fs, chirp slope S, and N ADC samples, the approximate sampled maximum range and range-bin spacing are:

Rmax ≈ c fs / (2S),     ΔR ≈ c fs / (2SN).

Mode 2 changes S. It therefore changes where beat frequencies map in range and extends the unambiguous range represented by the samples. It does not increase transmitted power, target radar cross section or antenna gain. A weak small UAV may still disappear well before the theoretical limit.

4.3 Expected trade-offs

  • Mode 2: wider unambiguous range, coarser range bins, no direct link-budget gain.
  • Mode 3: strongest possible receive-processing gain of the added modes, but only inside a limited manually centred sector and with calibration dependence.
  • Mode 4: wide electronic receive scan and simpler non-MIMO acquisition, but only four receive channels, a coarse angle grid, single-target PMM tracking and no transmit beam gain.

5 Operator interface, calibration and logging

5.1 Isolated deployment and reversibility

The extensions were added as separate copies. The original PMM application remains under main/. Modes 1–3 are in experimental_radar/, while the deployed four-mode application is in aesa_radar/. Separate desktop launchers preserve a recoverable baseline and prevent experimental profiles, logs and datasets from overwriting the root application by default.

5.2 Touch-oriented GUI and tactical display

The GUI exposes operation mode, display type, UART, capture duration, dataset destination, radar profile, network settings and PMM parameters without requiring terminal commands. Touch scrolling, responsive layout, larger controls and a maximised window support the portable monitor. The Mode 4 PPI presents the panel at the bottom centre, target position/trail and altitude indication in a familiar top-down format.

5.3 Calibration and readiness state

The PMM background is formed from a target-free 30-second interval. The PPI readiness banner is driven by the tracker’s actual accepted-frame count rather than a separate wall-clock timer. It displays amber calibration progress and instructs the operator to keep the field clear; it changes to green only when the tracker reports readiness. Search, target-track and classifier states are displayed separately to avoid treating calibration completion as target identification.

5.4 Classification boundary

The available LSTM classifier was trained and fingerprinted for Mode 1. Modes 2–4 change the waveform or array feature contract, so the GUI disables that model rather than applying an unsupported inference. PPI target annotations show a class and confidence only for a compatible classified run; otherwise they state that classification is off, warming or below the signal-quality gate. Valid classification in Modes 2–4 requires labelled captures from each intended configuration and retraining with capture-grouped validation.

5.5 Evidence logging

Each run can write processed PMM JSONL records and runtime-performance JSONL records. The logs retain PMM scores, thresholds, folding size, track state, estimated range/angle, frame timing, deadline misses, packet/capture integrity and sampled CPU/GPU/memory use. Raw complex ADC capture remains necessary for offline beam-weight optimisation because processed JSONL does not retain per-channel phase.

6 Planned final validation

6.1 Controlled comparison

  1. Use the same radar height, panel direction, target, route, environment and five-minute post-calibration duration for Modes 1–4.
  2. Mark measured ranges and bearings. Begin at 3, 5 and 8 m; increase only after stable nearer operation.
  3. Keep the field target-free until the readiness banner becomes green.
  4. For Mode 3, repeat at sector centres that place the target inside and outside the intended sector.
  5. For Mode 4, record target and radar height so relative-altitude error can be evaluated.
  6. Repeat each condition and include empty-scene runs to estimate false-alarm behaviour.

6.2 Measures

  • maximum confirmed static and moving-target range under a stated criterion;
  • confirmed-track coverage and detection probability at each distance;
  • false tracks during target-free intervals;
  • range, azimuth and relative-altitude error against measured references;
  • track fragmentation, reacquisition and incorrect distant snap events;
  • packets lost, invalid frames, queue/processing drops and stream resynchronisations;
  • pipeline p50/p95/max timing, deadline misses and CPU/GPU/memory use.

9 Limitations and future work

  • The four current GUI modes all use the PMM processing lane. The conventional teammate-developed pipeline is preserved in Git but has not yet been integrated as a fifth selectable lane.
  • The current PMM tracker intentionally follows one dominant target. Multi-target association and identity continuity are not established.
  • Mode 3 gain depends on phase calibration and target position within the sector. Mode 4 has only four physical receive channels and coarse two-dimensional angle estimates.
  • The lower-slope profile increases unambiguous range but does not guarantee sufficient SNR for a small drone at long range.
  • The classifier is not valid for Modes 2–4 until mode-specific labelled data are collected and a compatible model is trained.
  • A future comparison should deploy the conventional pipeline in a separate worktree/launcher first, then integrate it only after reproducing its baseline tests.
  • True transmit beam steering requires a separate hardware, power, phase-calibration, firmware and regulatory study; it is outside this implementation.

10 Conclusion

The repository still preserves both original team approaches, but only the PMM approach is directly selectable in the current four-mode application. The conventional CFAR/DBSCAN/CNN implementation remains recoverable from its Git branches and should not be described as removed, although it is not presently deployed in the new GUI. The present extension retains the original PMM mode as a control and adds three distinct experiments: sampled-range extension through a lower chirp slope, coherent directional receive gain through a twelve-channel sector beam bank, and non-MIMO electronic receive scanning through one transmitter and four receivers. It also adds a portable touchscreen workflow, tactical PPI, explicit calibration/readiness state, target annotation and structured evidence logging. These changes establish a controlled platform for evaluating range and directional sensitivity, but final performance conclusions remain pending the matched hardware tests defined in this report.
